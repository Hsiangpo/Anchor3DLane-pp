# 失败路线

本文件记录已经验证失败、训练中断或 F1 下跌的思路。后续实验必须先阅读本文件，避免重复试错。

## 已知失败方向

### 2026-05-10：仅调整 OpenLane evaluator `test_conf` 阈值

- 思路：复用官方 checkpoint 的 `output/openlane/baseline_eval/lane3d_prediction.json`，只扫描 evaluator 概率阈值，尝试在不重新训练的情况下提高召回。
- 代码改动：无。
- 已验证阈值与结果：
  - `test_conf=0.30`：F1 0.6220738690，recall 0.6312012725，precision 0.6132066740。
  - `test_conf=0.35`：F1 0.6231345955，recall 0.6269071922，precision 0.6194071325。
  - `test_conf=0.40`：F1 0.6237316446，recall 0.6221209333，precision 0.6253507179。
  - `test_conf=0.45`：F1 0.6239630964，recall 0.6175486651，precision 0.6305121788。
  - `test_conf=0.50`：F1 0.6240448139，recall 0.6132688508，precision 0.6352062468。
  - `test_conf=0.55`：F1 0.6238612686，recall 0.6085039909，precision 0.6400137828。
  - `test_conf=0.60`：F1 0.6235806539，recall 0.6033824799，precision 0.6451779268。
- 失败原因：降低阈值能提高 recall，但 precision 下降更快；提高阈值能提高 precision，但 recall 下降更快。F1 峰值仍是 baseline 的 `test_conf=0.50`，没有超过当前稳定 F1 0.6240448139。
- 后续避坑：不要再单独重复扫描 `test_conf=0.30..0.60`。后处理阈值只有在模型训练后输出分布改变时才重新小范围复查。

### 2026-05-10：visibility loss 从 SmoothL1 改为 BCE

- 思路：将可见性预测从连续回归式 SmoothL1 改为二分类 BCE，并给正样本加权，期望提高远处可见点判别能力和召回。
- 主要代码改动：
  - 在 `mmseg/models/losses/lane_loss_v2.py` 的 `LaneLossV2` 增加 `vis_loss_type`、`vis_pos_weight`、`vis_neg_weight`、`vis_eps` 参数。
  - 新增 `visibility_loss()`，当 `vis_loss_type='bce'` 时执行 `binary_cross_entropy`，并使用 `vis_pos_weight=1.5`、`vis_neg_weight=1.0` 加权。
  - 新增实验配置 `configs_v2/openlane/experiments/anchor3dlane++_r50x2_vis_bce.py`，从官方 checkpoint 加载，`lr=2e-5`，`max_iters=10000`，`samples_per_gpu=2`。
- 正式训练与评估：
  - 训练日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/train_vis_bce_retry_20260510_082812.log`。
  - 评估日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/eval_vis_bce_20260510_091100.log`。
  - checkpoint：`/root/autodl-tmp/Anchor3DLane-pp/output/openlane/experiments/vis_bce_r50x2/iter_10000.pth`。
  - 结果：F1 0.6235742314，recall 0.6226701761，precision 0.6244809158，cate_acc 0.9352928520。
- 失败原因：相比当前稳定 baseline F1 0.6240448139，F1 下跌约 0.0004706。BCE 提升了 recall，但 precision 下降明显，整体 F1 低于 baseline；说明直接把可见性回归改成 BCE 会改变置信分布，导致误检增加。
- 后续避坑：不要再单独尝试简单 BCE visibility loss 或只调 `vis_pos_weight` 的近似变体。后续若继续优化 visibility，应同时约束 lane-level confidence calibration 或匹配代价，否则容易用 recall 换 precision。

  - 新增实验配置 `configs_v2/openlane/experiments/anchor3dlane++_r50x2_quality_calib.py`，从官方 checkpoint 加载，`lr=2e-5`，`max_iters=10000`，`samples_per_gpu=2`，`quality_losses=0.1`。

### 2026-05-10：evaluator-aligned Hungarian matching

- 思路：OpenLane F1 由 3D lane 距离和可见点匹配决定，而原始 Hungarian matcher 主要用类别概率和可见 anchor 上的 Manhattan 距离做正样本分配。本实验在训练分配阶段加入 evaluator-inspired 的 clipped 3D distance cost，期望让正样本匹配更贴近最终 F1。
- 主要代码改动：
  - 在 `mmseg/models/losses/matcher.py` 的 `HungarianMatcher` 增加可选 `cost_eval`、`cost_vis`、`eval_dist_th` 参数。
  - 新增 `eval_distance_cost()`：对预测和 GT 的可见 `(x,z)` 点计算欧氏距离，按 `eval_dist_th=1.5` 裁剪归一化后参与匹配代价。
  - 新增 `visibility_cost()` 作为可选 visibility 分配代价，但本轮配置中 `cost_vis=0.0`，未启用。
  - 新增实验配置 `configs_v2/openlane/experiments/anchor3dlane++_r50x2_eval_match.py`，从官方 checkpoint 加载，`lr=2e-5`，`max_iters=10000`，`samples_per_gpu=2`，`cost_eval=0.5`。
- 正式训练与评估：
  - 训练日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/train_eval_match_20260510_110304.log`。
  - 评估日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/eval_eval_match_20260510_114446.log`。
  - checkpoint：`/root/autodl-tmp/Anchor3DLane-pp/output/openlane/experiments/eval_match_r50x2/iter_10000.pth`。
  - 结果：F1 0.6206571804，recall 0.6117780488，precision 0.6297978449，cate_acc 0.9319983737。
- 失败原因：相比当前稳定 baseline F1 0.6240448139，F1 下跌约 0.0033876。虽然训练稳定、无 OOM/NaN，且 matcher sanity 与 DDP smoke 都通过，但 evaluator-style clipped distance 作为分配代价会改变正样本归属，使分类和回归头学习到更保守但不更准的匹配；recall 和 precision 同时低于 baseline，说明该 proxy 与真实 OpenLane evaluator 的匹配收益不一致。
- 后续避坑：不要再单独在 Hungarian assignment 中加入 clipped 3D evaluator distance，也不要只调 `cost_eval` 或 `eval_dist_th` 做近似重复实验。若要继续做 evaluator alignment，必须把分配、采样和损失共同设计，并做小规模 ablation 验证正样本数量、距离分布和 precision/recall 变化。

### 2026-05-10：content-aware strip attention

- 思路：成功实验 `strip_sample` 对每个投影点使用全局固定的左/中/右 offset softmax 聚合，提升 precision 但 recall 下降。本实验在保留三点横向 strip sampling 的基础上，为每个 anchor point 增加轻量内容感知 offset 权重，期望远近、弯直、遮挡场景能自适应选择更可靠的局部证据。
- 主要代码改动：
  - 在 `mmseg/models/lane_detector/anchor_3dlane_pp.py` 中新增 `strip_agg='content'` 分支。
  - 新增 `strip_score_layer = nn.Linear(anchor_feat_channels, 1)`，对每个 anchor point 的每个 offset 特征预测动态权重。
  - `strip_score_layer` 零初始化，并叠加已有 `strip_weight_logits`，使其从 `strip_sample` checkpoint 启动时接近全局固定聚合。
  - 新增实验配置 `configs_v2/openlane/experiments/anchor3dlane++_r50x2_strip_content.py`，从 `strip_sample_r50x2/iter_10000.pth` 加载，`samples_per_gpu=3`，`lr=1e-5`，`max_iters=10000`。
- 正式训练与评估：
  - 训练日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/train_strip_content_20260510_151915.log`。
  - 评估日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/eval_strip_content_20260510_161629.log`。
  - checkpoint：`/root/autodl-tmp/Anchor3DLane-pp/output/openlane/experiments/strip_content_r50x2/iter_10000.pth`。
  - 结果：F1 0.6235247638，recall 0.6105797008，precision 0.6370306197，cate_acc 0.9359335635。
  - 对比当前稳定 `strip_sample`：F1 从 0.6252112086 降到 0.6235247638，下降约 0.0016864；recall 略高于 `strip_sample` 的 0.6098164673，但 precision 从 0.6414033570 明显降到 0.6370306197。
  - 对比官方 baseline：F1 也低于 0.6240448139。
- 失败原因：动态内容权重确实略微拉回 recall，但它破坏了 `strip_sample` 成功带来的高 precision。更细粒度的 offset 选择增加了局部特征聚合自由度，容易把邻近非车道纹理也聚合进 anchor point 表征，导致误检增加；这种误检代价超过了少量 recall 收益。
- 后续避坑：不要再做单独的 per-point/per-anchor 动态 offset 权重，也不要只换更深的 MLP、注意力头数或更多横向 offset 做近似重复。后续若继续改 strip sampling，优先研究带几何约束的候选抑制、lane-level 一致性约束或训练/推理联合排序，而不是增加局部聚合自由度。

### 2026-05-10：geometry-normal strip residual fusion

- 思路：成功实验 `strip_sample` 只在图像水平方向采样左/中/右局部特征。本实验保留稳定的 horizontal strip branch，再沿投影车道曲线的几何法向方向采样一组特征，并用一个全局标量门控 `strip_normal_alpha_logit` 做 residual fusion，期望在弯道或投影偏差方向不完全水平时补充更贴合车道几何的局部证据。
- 主要代码改动：
  - 在 `mmseg/models/lane_detector/anchor_3dlane_pp.py` 中临时新增 `strip_normal_sample`、`strip_normal_alpha_logit` 和 `normal_strip_sample()`。
  - `normal_strip_sample()` 根据相邻投影点估计曲线切向量，再取法向量进行 offset sampling；对 `anchor_feat_len <= 1` 和非有限切向量做了防御处理。
  - 新增实验配置 `configs_v2/openlane/experiments/anchor3dlane++_r50x2_strip_normal.py`，从 `strip_sample_r50x2/iter_10000.pth` 加载，`samples_per_gpu=3`，`lr=1e-5`，`max_iters=10000`。
- 正式训练与评估：
  - 训练日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/train_strip_normal_20260510_164642.log`。
  - 评估日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/eval_strip_normal_20260510_174102.log`。
  - checkpoint：`/root/autodl-tmp/Anchor3DLane-pp/output/openlane/experiments/strip_normal_r50x2/iter_10000.pth`。
  - 结果：F1 0.6238861006，recall 0.6163788492，precision 0.6315784776，cate_acc 0.9327178368。
  - 对比当前稳定 `strip_sample`：F1 从 0.6252112086 降到 0.6238861006，下降约 0.0013251；recall 从 0.6098164673 上升到 0.6163788492，但 precision 从 0.6414033570 明显降到 0.6315784776。
  - 对比官方 baseline：F1 也低于 0.6240448139。
- 失败原因：几何法向采样确实补回了一部分 recall，但显著破坏了 `strip_sample` 带来的 precision。OpenLane 远处车道投影很密集，法向方向不一定对应真实图像中“跨车道宽度”的方向；在遮挡、弯道和透视剧烈区域，法向 residual 更容易把邻近车道线、路沿或纹理引入 anchor feature，导致误检增多。全局标量门控不足以按场景抑制这些噪声，所以 F1 低于稳定版本。
- 后续避坑：不要再单独叠加 normal-direction strip sampling，也不要只调 `strip_normal_alpha_init`、offset 数量或门控初值做近似重复。若继续利用几何方向，应先设计可靠的候选抑制或 lane-level consistency 约束，让新增 recall 不以大幅 precision 损失为代价。

### 2026-05-10：curvature-enhanced 3D anchor prior

- 思路：Anchor3DLane++ 原始 3D anchor prior 主要由 `yaw`、`pitch` 和起始 `x` 生成，曲线形态依赖后续逐点 residual。本实验在 `reg_prior=True` 分支中增加一个零初始化的轻量二次曲率 prior，期望从 `strip_sample` 稳定 checkpoint 出发，让弯道和远处车道在进入 refinement 前已有更贴近真实形状的 3D 几何先验。
- 主要代码改动：
  - 在 `mmseg/models/lane_detector/anchor_3dlane_pp.py` 中临时新增 `curve_prior`、`curve_prior_mode`、`curve_prior_scale` 和 `apply_curve_prior()`。
  - 新增 `curve_prior_layer`，从 anchor feature 预测二次曲率系数；默认关闭，实验配置中开启 `curve_prior=True`、`curve_prior_mode='x'`、`curve_prior_scale=(2.0, 0.5)`。
  - 新增实验配置 `configs_v2/openlane/experiments/anchor3dlane++_r50x2_curve_prior.py`，从 `strip_sample_r50x2/iter_10000.pth` 加载，`samples_per_gpu=3`，`lr=1e-5`，`max_iters=10000`。
- 正式训练与评估：
  - 训练日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/train_curve_prior_20260510_181104.log`。
  - 评估日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/eval_curve_prior_20260510_190611.log`。
  - checkpoint：`/root/autodl-tmp/Anchor3DLane-pp/output/openlane/experiments/curve_prior_r50x2/iter_10000.pth`。
  - 结果：F1 0.6237906288，recall 0.6097665361，precision 0.6384749906，cate_acc 0.9328194036。
  - 对比当前稳定 `strip_sample`：F1 从 0.6252112086 降到 0.6237906288，下降约 0.0014206；recall 基本持平但略降，precision 从 0.6414033570 降到 0.6384749906。
  - 对比官方 baseline：F1 也低于 0.6240448139，下降约 0.0002542。
- 失败原因：零初始化曲率 prior 虽然训练稳定，但没有带来有效 recall 增益，反而降低 precision，并使近处横向误差变差（`x_error_close=0.20769`，高于 `strip_sample` 的 `0.19936`）。说明仅在 anchor 生成阶段加入自由二次曲率，会把部分本应由逐点 residual 自适应修正的几何偏差提前固化，容易产生系统性横向偏移；缺少显式曲率监督、lane-level 一致性约束和置信度校准时，新增形状自由度会扩大误检而不是提升匹配质量。
- 后续避坑：不要再单独尝试 learned quadratic anchor prior，也不要只调 `curve_prior_scale`、`curve_prior_mode='xz'` 或启用层数做近似重复。若继续研究曲率，应把曲率作为受约束的 lane-level regularization 或显式几何一致性目标，并同时评估 precision/recall、横向误差和候选排序，而不是只在 prior 中增加无监督形状自由度。
