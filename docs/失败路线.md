# 失败路线

本文件记录已经验证失败、训练中断或 F1 下跌的思路。后续实验必须先阅读本文件，避免重复试错。

## 已知失败方向

### 2026-05-13：TSP-LDT / Temporal Self-Supervised Pseudo-LiDAR Distillation Teacher

- 思路：在当前最高稳定 `ptef` 基础上做一次真正的大结构实验，而不是继续调小参数。TSP-LDT 离线用 same-segment 邻帧 lane set 生成 BEV/SDF/z/quality teacher cache；训练时让单帧模型在 proposal token 上采样这个 teacher field 做蒸馏，推理仍保持单帧输入，避免依赖真实时序位姿。
- 主要代码改动：
  - 新增 `tools/tsp_ldt/build_cache.py`，预生成 TSP-LDT teacher cache。
  - 新增 `mmseg/datasets/lane_datasets/openlane_tsp_ldt.py`，在 OpenLane 数据加载阶段读取 teacher `.npz`。
  - 修改 `mmseg/datasets/pipelines/lane_format.py` 与 `mmseg/datasets/__init__.py`，把 teacher tensors 纳入训练 batch。
  - 修改 `mmseg/models/lane_detector/field/lane_evidence_field.py` 与 `mmseg/models/lane_detector/anchor_3dlane_pp.py`，在现有 lane evidence field 上加入 TSP-LDT teacher sampling、distillation loss 和 `batch_tsp_*` 监控。
  - 新增实验配置 `configs_v2/openlane/experiments/anchor3dlane++_r50x2_tsp_ldt.py`，从 `output/openlane/experiments/ptef_r50x2/iter_10000.pth` 加载。
- 训练前验证：
  - 代码审查与复审通过，重点检查了 teacher 缺失处理、metric 命名、BEV feature 复用、张量维度、OOM 风险和 DDP 风险。
  - full teacher cache 生成完成：`data/OpenLane/lane3d_1000_v1.3/tsp_ldt_cache`，`136496 / 136496` 个 `.npz`。

- 后续避坑：
  - 不要把这条路线当作失败到完全丢弃；它有正信号，代码保留在归档分支 `archive/tsp-ldt-f1-62.627`，以后主线长期卡住时可以回看。
  - 不要继续只调 teacher cache 半径、loss weight、sampling 权重、batch size 或阈值，这会变成新的挤牙膏。
  - 如果重启 TSP-LDT，必须引入更强的 teacher-to-student precision 约束、lane-level false-positive suppression 或与新候选提交机制联合设计，而不是单独放大 teacher 蒸馏。

### 2026-05-12：SCD-CC / Shadow Candidate Distillation with Coverage-Constrained Commit

- 思路：在当前最高稳定 `ptef` 基础上，做一个候选生成与蒸馏路径层面的结构实验。SCD-CC 不把额外候选直接送入最终 NMS，而是在每条 public proposal 内部生成 4 个 shadow candidates，用 evaluator-style coverage / purity 信号训练 shadow 候选；推理时只通过极小的 commit gate 将 shadow 的加权残差压回原始 30 条 public proposals，试图获得更好的覆盖修正，同时避免 RQR-MPR/HPAS 那种新增候选导致的 precision 崩塌。
- 主要代码改动：
  - 新增 `mmseg/models/lane_detector/field/shadow_candidate_field.py`，实现 `ShadowCandidateField`，从 final-stage anchor tokens 生成 `[B, 30, 4, 86]` shadow proposals、quality logits、commit logits 和全局 commit gate。
  - 在 `mmseg/models/lane_detector/anchor_3dlane_pp.py` 中临时新增 `shadow_candidate_field` 构建、final-only 调用、loss 汇总和冻结训练白名单。
  - 在 `mmseg/models/lane_detector/field/__init__.py` 中临时导出 `ShadowCandidateField`。
  - 新增实验配置 `configs_v2/openlane/experiments/anchor3dlane++_r50x2_scd_cc.py`，从 `output/openlane/experiments/ptef_r50x2/iter_10000.pth` 加载，`samples_per_gpu=3`，`lr=1e-5`，`max_iters=10000`，只训练 `accept_calib_head` 与 `shadow_candidate_field`。
- 关键代码片段：
  - `shadow = proposals[:, :, None, :].expand(-1, -1, num_modes, -1).clone()`，每条 public proposal 生成多个内部 shadow 模式。
  - `mode_scores = quality_logits.softmax(dim=2) * commit_logits.sigmoid() * commit_gate.sigmoid()`，把 shadow 质量和 commit 置信度合成内部提交权重。
  - `proposals[:, :, 5:5 + anchor_len] += commit_dx`，只把加权残差写回原 30 条 public proposals，不增加最终输出候选数。
- 训练前验证：
  - 本地 `py_compile` 和 `git diff --check` 通过。
  - 代码审查子代理初审发现 blocking reshape 与 high NaN 风险，修复后复审 APPROVE。
  - 远端 config/model/checkpoint load 通过，预期缺失键仅为 `shadow_candidate_field.*`，`unexpected=[]`。
  - standalone forward/backward 通过：`out_props=(2,30,86)`，`shadow=(2,30,4,86)`，`commit_gate_logit` 与 `shadow_head.4.*` 梯度有限。
  - 1-iter 和 20-iter 双卡 DDP smoke 通过，`samples_per_gpu=3`，显存约 `18976MB`，无 OOM/NaN/Traceback/Killed/DDP hard error。
- 正式训练与评估：
  - 训练日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/train_scd_cc_20260512_163501.log`。
  - checkpoint：`/root/autodl-tmp/Anchor3DLane-pp/output/openlane/experiments/scd_cc_r50x2/iter_10000.pth`。
  - 评估日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/eval_scd_cc_bg_20260512_171716.log`。
  - 结果文件：`/root/autodl-tmp/Anchor3DLane-pp/output/openlane/experiments/scd_cc_r50x2_eval/evaluation_result.json`。
  - 结果：F1 `0.6260829149193411`，recall `0.6172490780566791`，precision `0.6351732761700607`，cate_acc `0.9350982224648611`，`x_error_close=0.2009763014`，`x_error_far=0.2384072078`，`z_error_close=0.0732474769`，`z_error_far=0.1004802460`。
- 失败原因：
  - 相比当前最高稳定 PTEF F1 `0.6260965689592046`，下降约 `0.0000136540`，也就是 0-100 分制下降约 `0.001365` 分；虽然差距极小，但没有超过当前稳定版本，必须回滚。
  - 指标形态是 precision 从 PTEF 的 `0.6351636182` 微升到 `0.6351732762`，但 recall 从 `0.6172847432` 降到 `0.6172490781`；SCD-CC 只带来极小 precision 置换，没能补足额外真阳性。
  - `batch_shadow_delta` 在正式训练末期仍约 `0.0001`，说明 commit gate 过于保守。shadow branch 学到了内部 coverage/quality 信号，但几乎没有把几何残差真正提交回 public proposals，因此对最终 OpenLane 匹配影响非常弱。
  - 更本质地说，SCD-CC 刻意避免了 RQR/HPAS 的“额外候选进 NMS”风险，但代价是 shadow 候选缺少一个强 lane-level commit/reranking 机制。仅靠极小 residual commit 无法解决候选覆盖与最终提交质量之间的核心矛盾。
- 后续避坑：
  - 不要再单独重复“内部 shadow candidates + 极小 residual commit gate”的 SCD-CC 形式。
  - 不要只调 `num_modes`、`gate_init`、`commit_bias_init`、shadow loss 权重、coverage/purity 阈值或 delta scale 做近似重复实验。
  - 如果继续研究 shadow / recall-reserved candidates，必须引入更强的二阶段 lane-level commit reranker、road-ribbon SDF 质量评分或 evaluator-aligned suppression，而不是只让 shadow 小残差回写到 public proposal。

### 2026-05-12：BRF-LPF / Bypass Recall Floor for Lane-Point Field

- 思路：在当前最高稳定 `strip_sample + vdcc + eac_dr + frt_eat + lpf_t` 基础上，解决 LPF-T 提升 precision 但轻微压低 recall 的问题。BRF-LPF 不新增候选、不改 matcher/NMS/阈值、不把 near-GT unmatched proposal 改成正样本，而是在 final stage 用 LPF-T 前的 no-grad bypass teacher proposals 做 one-sided score floor：只有 teacher 与 student 都 evaluator-clean 且归属同一 GT lane 的 slot，才保护 student 分数不要低于 teacher。
- 主要代码改动：
  - 在 `mmseg/models/lane_detector/anchor_3dlane_pp.py` 中临时新增 `recall_guard`、`build_recall_guard()`、`use_recall_guard()` 和 `predict_from_anchor_features()`，在 LPF-T 前用 `torch.no_grad()` 生成 teacher proposals / teacher accept logits。
  - 在 `mmseg/models/losses/lane_loss_v2.py` 中临时新增 `recall_guard_losses`、`recall_guard_score_margin`、`recall_guard_accept_margin`、`recall_guard_rank_margin`、`recall_guard_rank_topk` 等参数。
  - 新增 `recall_guard_loss()` 和 `recall_guard_rank_loss()`，只对 teacher-confirmed 且 student evaluator-clean 的 owner slot 施加 score/accept/rank 地板约束。
  - 新增实验配置 `configs_v2/openlane/experiments/anchor3dlane++_r50x2_brf_lpf.py`，从 `output/openlane/experiments/frt_eat_r50x2/iter_8000.pth` 加载，`samples_per_gpu=3`，`lr=2e-5`，`max_iters=10000`，`recall_guard_losses=0.02`。
- 关键代码片段：
  - `with torch.no_grad(): teacher_proposals, _, teacher_accept_logits = self.predict_from_anchor_features(batch_anchor_features.detach(), ...)`
  - `owner_mask = teacher_accepted & student_accepted & same_best_target`，实际实现按每个 target 只取 teacher cost 最低的 owner slot。
  - `score_floor = relu(teacher_score - recall_guard_score_margin - student_score)`，只在 student 低于 teacher 地板时生效。
- 训练前验证：
  - 本地与远端 `py_compile`、目标文件 `git diff --check` 通过。
  - 代码审查子代理 PASS：无 blocking/high/medium；teacher bypass 无反向图泄漏，DDP/log tensor 类型安全，冻结训练只放行 `lane_point_field.*` 和 `accept_calib_head.*`。
  - 远端 config/model/checkpoint load 通过；预期缺失键仅为 `lane_point_field.*`，训练参数只包含 `lane_point_field.*` 与 `accept_calib_head.*`。
  - synthetic sanity 通过：构造 teacher 强、student 弱的同 owner proposal 时 `guard_loss` 有限且非零，空 target 和 `teacher=None` 安全返回 0。
  - 1-iter 和 20-iter 双卡 DDP smoke 通过，`samples_per_gpu=3`，显存约 `18976MB`，`batch_recall_guard_owner_pos` 非零，无 OOM/NaN/Traceback/Killed/DDP hard error。
- 正式训练与评估：
  - 训练日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/train_brf_lpf_20260512_093248.log`。
  - checkpoint：`/root/autodl-tmp/Anchor3DLane-pp/output/openlane/experiments/brf_lpf_r50x2/iter_10000.pth`。
  - 评估日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/eval_brf_lpf_20260512_100542.log`。
  - 结果文件：`/root/autodl-tmp/Anchor3DLane-pp/output/openlane/experiments/brf_lpf_r50x2_eval/evaluation_result.json`。
  - 结果：F1 `0.6256699349570143`，recall `0.6124200209710898`，precision `0.6395058602228332`，cate_acc `0.9365190648457145`，`x_error_close=0.1989899224`，`x_error_far=0.2366950685`，`z_error_close=0.0730844025`，`z_error_far=0.1001515818`。
- 失败原因：
  - 相比当前最高稳定 LPF-T F1 `0.6256777375241412`，下降约 `0.0000078`；虽然只差约 `0.00078` 个 0-100 分制点数，但仍然没有超过当前稳定版本，必须回滚。
  - 指标形态是 precision 从 `0.6394210764` 微升到 `0.6395058602`，但 recall 从 `0.6125127503` 微降到 `0.6124200210`；BRF-LPF 没有补回 LPF-T 的召回损失，反而把一点 recall 换成了极小 precision。
  - 更本质地说，LPF-T 前后的 teacher/student 共享同一候选 slot 和大部分冻结头，teacher floor 只在 student 低于 teacher 时才触发。训练日志里 `recall_guard_losses` 长期接近 0，说明该约束太弱，主要只能防止极少数 slot 分数倒退，不能主动扩大 evaluator-positive 覆盖或改变候选排序。
  - BRF-LPF 的 owner 选择过于保守：必须 teacher-clean、student-clean、同 target 才保护，这避免了 MP-BFR 式错误正样本，但也导致它无法处理真正丢召回的情况，因为那些 student 已经不 clean 的候选不会被拉回来。
- 后续避坑：
  - 不要再单独重复 LPF 前 no-grad bypass teacher score floor 的 BRF-LPF 形式。
  - 不要只调 `recall_guard_losses`、`recall_guard_score_margin`、`recall_guard_accept_margin`、`recall_guard_rank_margin`、`recall_guard_rank_topk` 做近似重复。
  - 后续若继续保护 LPF-T 的 recall，必须让 teacher 信号能覆盖 student 已经掉出 evaluator-clean 的候选，或引入更强的 lane-level recall teacher / contrastive ownership，而不是只做同 slot one-sided score floor。

### 2026-05-12：MP-BFR / Multi-Positive Boundary Fine Refinement

- 思路：在当前最高稳定 `strip_sample + vdcc + eac_dr + frt_eat` 基础上，解决 Hungarian 一对一分配导致正样本过少的问题。MP-BFR 不改 30 个推理候选、不改 NMS、不改阈值，而是在 final-only loss 中把 clean duplicate 和 near-GT repair proposals 从分类负样本池中移除，并给它们额外几何/可见性监督；FRT dirty proposals 只允许 ignore，避免跨邻车道候选被错误强化。
- 主要代码改动：
  - 在 `mmseg/models/losses/lane_loss_v2.py` 的 `LaneLossV2` 中临时新增 `boundary_refine_losses`、`boundary_clean_topk`、`boundary_repair_topk`、`boundary_cover_thresh`、`boundary_purity_thresh`、`boundary_dist_thresh`、`boundary_vis_weight` 等参数。
  - 新增 `pair_metrics()`、`select_boundary_pairs()`、`boundary_refine_loss()`，用 evaluator-style cover/purity/hit_count 选出 clean/repair proposals，并对选中 proposal 执行 x/z/visibility 监督。
  - 修改负样本构造逻辑：`negatives_mask[boundary_ignore] = False`，让 clean/repair/dirty-ignore proposal 不再进入背景分类损失。
  - 新增实验配置 `configs_v2/openlane/experiments/anchor3dlane++_r50x2_mp_bfr.py`，从 `output/openlane/experiments/frt_eat_r50x2/iter_8000.pth` 加载，`samples_per_gpu=3`，`lr=1e-5`，`max_iters=10000`，`boundary_refine_losses=0.10`。
- 关键代码片段：
  - `pair_repair = (cover >= boundary_cover_thresh) & (purity >= boundary_purity_thresh) & (hit_count >= boundary_min_hits) & (hit_cost <= boundary_dist_thresh) & pair_clean & ~pair_accept_clean`
  - `safe_candidate = ~dirty_ignore`，防止 FRT dirty proposals 被 clean/repair 监督。
  - `negatives_mask[boundary_ignore] = False`，把 near-GT boundary proposals 从背景负样本中移除。
- 训练前验证：
  - 本地与远端 `py_compile`、`git diff --check` 通过。
  - 远端 config/model/checkpoint load 通过，`missing=[]`、`unexpected=[]`。
  - synthetic sanity 通过：exact duplicate 被选为 clean，1.8m near-GT 被选为 repair，far proposal 仍为 negative，cross-neighbor FRT dirty 只进入 ignore。
  - code review 子代理发现 FRT dirty 可能被 clean/repair 选中的高风险问题；已用 `safe_candidate = ~dirty_ignore` 修复。
  - 1-iter 和 20-iter 双卡 DDP smoke 通过，`samples_per_gpu=3`，显存约 `27398MB`，`batch_boundary_repair` 非零，无 OOM/NaN/Traceback/Killed/DDP hard error。
- 正式训练与评估：
  - 训练日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/train_mp_bfr_20260512_064029.log`。
  - checkpoint：`/root/autodl-tmp/Anchor3DLane-pp/output/openlane/experiments/mp_bfr_r50x2/iter_10000.pth`。
  - 评估日志：`/root/autodl-tmp/Anchor3DLane-pp/logs/eval_mp_bfr_20260512_074729.log`。
  - 结果文件：`/root/autodl-tmp/Anchor3DLane-pp/output/openlane/experiments/mp_bfr_r50x2_eval/evaluation_result.json`。
  - 结果：F1 `0.621979854494763`，recall `0.6121061679256453`，precision `0.6321773020348785`，cate_acc `0.9339583080951627`，`x_error_close=0.2037659573`，`x_error_far=0.2383443851`，`z_error_close=0.0728240871`，`z_error_far=0.0999073509`。
- 失败原因：
  - 相比当前最高稳定 FRT-EAT F1 `0.6255466703380164`，下降约 `0.0035668`；相比官方 baseline F1 `0.6240448139487519`，也下降约 `0.0020649`，必须回滚。
  - 指标形态是 recall 从 FRT-EAT 的 `0.6164715785` 降到 `0.6121061679`，precision 从 `0.6348929435` 降到 `0.6321773020`，说明 MP-BFR 同时削弱了召回和精度，不是良性的 precision/recall 置换。
  - 更本质地说，near-GT unmatched proposal 并不一定是“应该被修复的潜在正样本”。在 3D lane 场景里，很多 near-GT proposal 可能是局部点接近但 lane-level 拓扑、可见范围或候选排序质量不可靠的边界样本。把它们移出背景负样本并增加几何监督，会削弱分类头对低质量候选的抑制能力，同时把回归头拉向模糊边界，最终破坏 FRT-EAT 已经形成的候选排序平衡。
  - MP-BFR 的 clean/repair 选择依赖 evaluator-style cover/purity 代理指标，但该代理仍无法表达完整 OpenLane 匹配中的 lane-level 唯一性、拓扑归属和候选间竞争；因此“多正样本修复”在理论上增加监督密度，实际却给模型加入了错误或弱质量正样本。
- 后续避坑：
  - 不要再单独重复“把 near-GT unmatched proposals 从背景池移除并施加额外几何监督”的 MP-BFR 形式。
  - 不要只调 `boundary_refine_losses`、`boundary_clean_topk`、`boundary_repair_topk`、`boundary_cover_thresh`、`boundary_purity_thresh`、`boundary_dist_thresh` 或 visibility 权重做近似重复。
  - 后续若继续研究多正样本或 boundary proposal，必须显式建模 lane-level 唯一性、topology ownership 或 teacher-student ranking，不能只靠 cover/purity 阈值把边界候选改成软正样本。

### 2026-05-12：PC-Aug / Projection-Consistent Camera Augmented Fine-tuning

- 思路：在当前最高稳定 `strip_sample + vdcc + eac_dr` 基础上，尝试投影一致的相机视角增强。具体做法是在训练 pipeline 中对原图施加小幅 affine/projective 扰动，同时把同一个 2D homography 左乘到 `gt_project_matrix` / `gt_homography_matrix`，并把增强后投影到图外的 GT 点 visibility 清零；然后从 EAC-DR checkpoint 进行全模型低学习率微调，期望提升对相机扰动、轻微标定偏差和图像裁切变化的泛化。
- 主要代码改动：

### 2026-05-11：PF-ATM / Pose-Free Anchor Token Memory
